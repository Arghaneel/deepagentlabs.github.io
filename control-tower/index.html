    Why it exists

    More agents, less visibility.

    Teams start with one agent and soon run dozens, across different frameworks, machines and owners. Without one shared list, nobody can answer simple questions quickly.

    “Which agents do we even have?”

    Agents live in different repos, notebooks and services. There is no single inventory.

    “Is anything broken right now?”

    An agent that silently stops working is often noticed only when a user complains.

    “Which tools does each one use?”

    Versions drift, and nobody knows which agent has AgenticLens, Sidecar or MCP, or which one is missing them.

    Control Tower answers all three from one console: a fleet view of your agents, their health and the tools each one runs.

    What it does

    See every agent, know what needs attention.

    Control Tower turns a scattered set of agents into one fleet you can read at a glance: who runs what, how healthy it is, and which tool to add next.

    Two ways to run it

    Your machine, or ours.

    Both use the same console. Pick the setup that fits you.

    Self-hosted

    Available as a Python package

    Run it yourself

    Install Control Tower on your laptop or your own server. You sign in with an account that lives on that install, and nothing is sent to DeepAgentLabs: your agent inventory and history stay on the machine that runs it.

    Account
    A local account on your install. No DeepAgentLabs sign-up.
    Where it runs
    Your machine or your own server.
    Where data lives
    Local to that machine. No central database.
    Install
    pip install agenticops-control-tower

    Best for: individual developers, and teams that need data to stay on their own infrastructure.

    Hosted

    Planned · preview only

    DeepAgentLabs runs Control Tower in the cloud. You sign in from any browser and your workspace is stored centrally, so your whole team sees the same fleet without running servers.

    How it works

    Up and running in four steps.

    Steps 3 and 4 use commands that are in the repository and ship in the next release (they need the api extra).

    1. 1

      Install

      Add the Python package. Today it gives you the registry, discovery and status Python API.

      pip install agenticops-control-tower
    2. 2

      Describe your fleet

      Register your agents with where they run and which tools they use, or start from the example snapshot in the repository.

      examples/sample_fleet_snapshot.json
    3. 3

      Start the server

      Serve the console and API from your machine, loading a fleet snapshot.

      agenticops-control-tower serve --snapshot examples/sample_fleet_snapshot.json
    4. 4

      Check the fleet

      Open the Fleet page in the console, or ask for the fleet status from the command line.

      agenticops-control-tower status

    Health at a glance

    Four states, no guesswork.

    Every agent gets one simple status, so the fleet view shows straight away where to look first.

    • HealthyChecking in and reporting no problems.
    • DegradedStill running, but reporting problems. Worth a look.
    • UnhealthyNot working as it should. Needs attention now.
    • UnknownNo status reported yet.

    Is Control Tower free?

    Yes. It's open source and free to use, like every DeepAgentLabs package.

    Does my data leave my machine?

    Not when you self-host. Your agent inventory and history stay on the machine that runs Control Tower, with a local account and no central database. The hosted version, when it arrives, stores your workspace in the DeepAgentLabs cloud.

    Is the chat an AI model?

    Not yet. Answers come from the DeepAgentLabs catalog of tools. Connecting an AI model is planned.

    Can I use it today?

    Yes, as a Python package: v0.2.0 on PyPI gives you the registry, discovery and status API. The serve command and the CLI ship in the next release, and the console is a preview.

    Which frameworks does it support?

    Any. The sample fleet includes agents built with LangGraph and the OpenAI Agents SDK, running on AWS Lambda and Docker.

    Where do I ask questions or report bugs?

    Open an issue on GitHub, request a feature from inside the console, or ask on Discord.
