The milestones

Eight steps from a draft to a stable standard.

v0.1 · Core concepts In review

Define what exists inside a running AI system.

The foundation: a shared meaning for every runtime occurrence, with clear boundaries between them.

  • A Workflow is a definition; a Run is one execution of it.
  • Model calls, tool calls, retrieval and memory stay distinct occurrences.
  • A reliability event is evidence. It doesn't automatically become an Incident.

Done when two independent teams classify the same runtime events the same way.

v0.2 · Relationships Exploratory draft

Show how the pieces connect into execution graphs.

Real agent runs branch, retry, loop and hand off. v0.2 makes every one of those relationships explicit.

  • Workflow → Run → Request hierarchy and parent–child Runs.
  • Sequential, parallel, branch/join, retry and loop semantics.
  • Agent participation and handoff patterns.

Done when two tools draw the same execution graph.

run graph

Explicit edges: containment, ordering, causation, dependency, handoff

v0.3 · Semantics Exploratory draft

Give every event one name and one meaning.

Canonical, transport-neutral events with clear lifecycles across runs, agents, models, tools, memory, evaluation, safety and incidents.

  • Canonical event names and naming rules.
  • Lifecycle meanings: what started, finished or failed.
  • The minimum attributes needed to interpret each event.

Done when producers and consumers agree on what each event means.

v0.4 · JSON Schemas Exploratory draft

Turn the spec into artifacts that machines can check.

Workflow and Run schemas, plus validation fixtures, all derived from v0.1–v0.3. Two conformance artifacts already pass.

  • Structural validation: is the artifact the right shape?
  • Semantic validation: do references resolve, and is every graph acyclic?
  • Passing today: AgenticLens and Agentic Chaos sample runs.

Done when artifacts validate without any DeepAgentLabs package.

v0.5 · Versioning Planned

Know whether an artifact is safe to consume.

Version markers and change rules so the spec can evolve without breaking the tools that read it.

  • Artifact version markers.
  • Additive vs. breaking change rules, and a deprecation policy.
  • Expected behaviour when a consumer meets a newer version.

Done when anyone can tell if an artifact is safe to consume.

  • New optional fieldadditive · safe

v0.6 · Examples & extensions Planned

Let anyone extend the spec without forking it.

Canonical example artifacts, from minimal to advanced, plus clear rules for third-party extensions.

  • Minimal and advanced canonical artifacts.
  • Reverse-domain namespaces for vendor data.
  • The spec owns conformance; tools only make it convenient.

Done when third parties can extend the spec without forking it.

attributes
"attributes": {
  "io.deepagentlabs.agenticlens.cost_usd": 0.0042,
  "com.yourcompany.team": "support"
}

Unknown namespaces are preserved, never rejected

v0.6.x · Provenance & evidence Planned

Show where every finding came from.

Attach source references and lineage to findings, and give producers a conformance suite they can run on their own.

  • Provenance concepts: sources, lineage, derived findings.
  • An independent conformance test suite and fixtures.
  • Next: OpenTelemetry GenAI binding, audit and verification schemas, hosted docs.

Done when producers can run conformance checks on their own.
